The rule that shapes everything below

A model is never asked how many days a batch has left, what a run yielded, what should be loaded next, whether the mass balance holds, or what a batch’s parents and children are. Every one of those has a right answer a query can produce. They are answered by ordinary code, and the request never reaches a model.

Positioning

Where this differs from an agent-per-function design

Routing

Fewer agents, not more

The common pattern puts a specialised agent in front of each function: validation, ordering, monitoring, reporting. Here the router's first job is to decide the request does not need a model at all, and most requests do not.

Trust

Nothing gets rebuilt to be re-agented

A stock tracker and a yield report already exist and staff use them daily. A second screen that eventually disagrees with the first does not get adjudicated, it gets both screens distrusted. The rule is to find out whether a screen exists before building one.

Accountability

The pipeline never files anything

Automated output stops at a draft. A named human signs, and the timestamp lands on the record with the model id, the prompt version, the token counts and the cost.
