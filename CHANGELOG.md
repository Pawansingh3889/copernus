# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/);
versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed

- All 18 strict-mypy errors: DML results narrowed to `CursorResult` before reading
  `rowcount`; `User | None` / `IdentityRecord | None` no longer assigned to
  non-optional variables; return annotations on every route handler; generic
  arguments on `Row`, `Result`, `async_sessionmaker` and the audit sink.

### Added

- Domain docs: label control documented as reel reconciliation — reels of 1,500 or
  2,000 labels issued and returned by count and weight, with Dimaco verification at
  start of run, every reel change, and end of run (`docs/domain/business-rules.md` §6).
- This changelog.
- A 1–2 line plain-English description comment at the top of every code file.

### Changed

- `ARCHITECTURE.md` §8: three assistant decisions recorded ahead of Phases 8–9 —
  prompts are code (source tree, eval-gated on every change), captured shop-floor
  text enters prompts as data never instructions (prompt isolation as
  architecture), and every assistant record carries model id, prompt version,
  token counts and cost, with prompt caching over the stable corpus. `ROADMAP.md`
  P9 builds/gate updated to match.
- `docs/domain/business-rules.md` §5: intake lot code decoded — `F6160B` = fresh ·
  2026 · Julian day 160 · second batch of the day. Day 160 is 9 June, two days
  before the tag's printed 11.06 harvest date, so the code anchors an earlier
  event (wellboat loading, likeliest — unverified); printed dates stay
  authoritative and the code stays opaque (`data-model.md` §1 cross-references).
- `make gate` now includes `typecheck` (strict mypy), so CI enforces it on every
  push; `tests/test_gates.py` proves it rejects a planted type error from a cold
  cache.
- `docs/domain/business-rules.md`: quality-check facts verified against shop-floor
  records and SI screens — observed metal-detection apertures (Fe 2.5 / SS 4.0 /
  NF 3.0 mm), the < 4 °C temperature target, region of capture per batch code (from
  the retail traceability sheet into the run paperwork), and SI as the existing system of record for
  units and weights (the paper record covers only the checks themselves). A second
  observed intake tag confirms the 18-day constant across a different supplier.
- `docs/domain/data-model.md` §1: run numbers are zero-padded six-digit strings at
  source (`035366`); leading zeros are significant when matching labels.
- `docs/domain/data-model.md` §1 and `business-rules.md` §6: finished product goes
  into baskets or boxes whose barcode labels are generated by OCM — the case barcode
  is a distinct artifact from the reel-fed pack label.
- `docs/domain/data-model.md` §4: each department opens its own run with its own
  yield (tempering, filleting/portioning, curing/smoking, retail packing); genealogy
  edges are made by container scans — OCM basket/box barcode with tare, booked as
  output of one run and scanned as input of the next, weight on both sides.
- `docs/domain/business-rules.md` §6: reel reconciliation denominator confirmed —
  all packs labelled (accepted, reworked, wasted) plus damaged labels, not the
  checkweigher's accepted count.
- `docs/domain/business-rules.md` §7: the checkweigher summary already lands in the
  SI database — eliminating the hand-copy is a read, not a build.
- `docs/domain/business-rules.md` §5/§6: concessions live on a paper form filed with
  the run paperwork (no queryable form today); region of capture arrives on the
  supplier trace tag and is keyed in at goods-in; reel issue/return movements are
  stock movements in SI.
- `docs/domain/data-model.md` §4: same-shift rework re-enters the same run (no
  genealogy edge), held-over rework opens its own later run — edge-level cycles are
  rare but real.
- `docs/domain/data-model.md` §3: the certification schemes named — GlobalG.A.P. and
  RSPCA Assured (farmed salmon, separate material streams), MSC (wild-caught
  whitefish); a certification claim is also a segregation constraint.
- `docs/domain/business-rules.md` §8 (new): product value tiers off the chopper
  (cod loins → fillets → simply; salmon 140 g → 120 g → 110 g → simply) and the
  certification ladder (RSPCA premium above GG/standard; downgrade = cost,
  upgrade = breach).
- `docs/domain/data-model.md` §4: basket constants (36 packs/basket, 2.25 kg tare,
  16 baskets/pallet); a wrong tare once biased yield by 14 kg per pallet.
- `docs/domain/business-rules.md` §5: C3 answered — the 18 days anchors on the
  harvest/kill date; superchilling is a per-customer-order decision.
- `docs/domain/data-model.md` §2: composite batch codes concentrate in tier-3 runs
  (marinade, simply) fed by OCM scan-back returns.
- All §5 open questions answered: C1 superchill separates classes (order attribute),
  C2 total stays 18, C4 concession capped at pack + 10, C5 harvest window = minimum
  life remaining. D1 answered: GRN sparse/unreliable, never authoritative.
